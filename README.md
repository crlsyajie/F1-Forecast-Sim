# F1 Forecast Simulator

An unofficial fan project that predicts Formula 1 race results with XGBoost and replays them as a live race on real circuit maps.

**Live site:** https://crlsyajie.github.io/F1-Forecast-Sim/

## What's on the site

- **Simulator** – race or sprint replay: cars race around the real track outline at their predicted pace, with a broadcast-style timing tower (intervals, overtakes, fastest lap) and race banners.
- **Weekend** – qualifying prediction from practice pace and recent form, and the sprint prediction next to the real sprint result.
- **Tracks** – every circuit on the 2026 calendar, drawn from FastF1 position data.
- **Inputs** – rain chance, temperature and an editable qualifying grid. The model reruns in the browser.
- **Model** – accuracy on held-out races, feature importance, and predicted vs actual podiums for completed 2026 rounds.

## Main model

The race prediction shown by default comes from the **Formula 1 GP Predictor** notebook (a qualifying-based XGBoost model with
monotone constraints and calibrated win/podium chances). It is updated in that project with the `/f1-gp-update` skill, which
writes `~/.f1-gp-predictor/data/prediction.json`; `pipeline/build_site.py` reads that file (read-only) and bundles it into the
site. Where it has no prediction (other rounds, the sprint), the site says so and shows a secondary model instead.

## How the model works

- Training data: every race from 2024 to 2026 round 9 via [FastF1](https://github.com/theOehrly/Fast-F1), one row per driver.
- Features: qualifying gap to pole (%), grid position, the team's best qualifying gap, rain, air temperature.
- Target: the driver's median green-flag race lap, as % slower than the fastest driver.
- Two models on the same data: XGBoost (with monotone constraints) and a Random Forest. The site lets you pick either one or their average. Race-grouped 80/20 train/test split. The trained trees are exported to JSON and evaluated in the page's JavaScript, so predictions update instantly.
- Held-out error: 0.63% of lap time (about 0.6 s/lap), versus 0.85% for predicting the average and 0.80% for a qualifying-gap-only line.

## Repo layout

```
web/                       React + Vite front end (deployed to GitHub Pages)
  src/App.jsx              navigation and shared state
  src/components/          Simulator, Tracks, Inputs and Model pages
  src/lib/model.js         XGBoost trees evaluated in the browser
  src/lib/race.js          race engine: per-lap times, gaps, finishing order
  src/lib/broadcast.js     timing tower state and race events
  src/lib/geo.js           circuit geometry and canvas drawing
  src/data/site-data.json  generated by pipeline/build_site.py
pipeline/train.py          trains XGBoost + Random Forest race models, exports trees + metrics to data/model.json
pipeline/train_quali.py    qualifying model (practice gap, team gap, recent form) -> data/quali_model.json
pipeline/practice.py       downloads each training weekend's final practice session
pipeline/build_site.py     packs model, tracks and results into web/src/data/site-data.json
pipeline/refresh.py        race-day refresh: OpenWeather forecast + qualifying grid, then rebuild
pipeline/tracks*.py        downloads circuit outlines and corner numbers from FastF1
data/                      training data, grid, practice pace, tracks, trained model
docs/                      built site served by GitHub Pages (generated, do not edit)
```

## Run the front end

```bash
cd web
npm install
npm run dev        # local dev server
npm run build:docs # production build, copied to ../docs for GitHub Pages
```

## Refresh the data

The site follows whichever race the main model (Formula 1 GP Predictor) is predicting.

1. Update the main model with the `/f1-gp-update` skill (it pulls FastF1 / tif1 timing data and the OpenWeather forecast).
2. Rebuild this site from its output:

```bash
venv/bin/python pipeline/refresh.py   # reads ~/.f1-gp-predictor/data read-only, retrains the secondary models, builds web/
```

`refresh.py` makes no FastF1 or OpenWeather calls of its own (F1's live-timing server has returned 401 since Oct 2026).
Commit and push to deploy.

## Deploy

GitHub Actions (`.github/workflows/deploy.yml`) builds `web/` and publishes it to GitHub Pages on every push to `main`. In the repo settings, set **Pages → Build and deployment → Source** to **GitHub Actions**.

The `docs/` folder holds the same build for **Deploy from a branch → /docs**, as a fallback that needs no Actions. Refresh it with `npm run build:docs` in `web/`.
